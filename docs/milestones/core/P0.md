**P0.2** — Contract gaps found by reading `contracts/jsonschema/*` against `docs/contracts/DOMAIN_AND_EVIDENCE_CONTRACT.md`; each fix needs a failing negative fixture first:
- `verification_decision.v1`: nothing enforces `published_eligible = true ⇒ business_verdict = VERIFIED ∧ comparison_status = EQUAL` (SOURCE_CUT_PROTOCOL §12). Expressible with `if/then`.
- `source_receipt.v1`: `logical_request_id` is required for `source_kind = INVOICE`, but invoice rows are not necessarily attributable to a logical request; decide the invoice identity model explicitly.
- `source_receipt.v1`: `outcome = PROVIDER_CONFIRMED_BILLED` does not require `provider_attempt_id`/`provider_generation_id` or `known_provider_cost_usd` (INV-02).
- Money pattern `^(0|[1-9][0-9]*)(\.[0-9]+)?$` allows unbounded scale; pin the declared precision (INV-05).
- No `transport_delivery_id` anywhere although the contract distinguishes it from `source_event_id`; decide where it lives (Kafka metadata, receipt, or both).
- Gate states: contract lists `HUMAN_GO/HUMAN_NO_GO`, P1.5 and the milestone index use CONDITIONAL GO. The validator accepts `HUMAN_CONDITIONAL_GO`; add it to the contract or drop it, consistently.
- Inputs: `docs/research/OSS_REFERENCE_REGISTER.md` #1 OpenMeter (dedup boundary) and #3 Lago (study-only, AGPL).

**P0.3** — Inputs: register #2 Debezium outbox example (design read only; the runnable lab belongs to P2.2/P4.1). The ERD must show which unique key distinguishes each identity in the domain contract.

**P0.4** — Toolchain risks observed on the owner's host on 2026-11-19 (Python 3.14.4, Java 23, Docker 29.9.3). Public sources consulted then; re-confirm before pinning:
- Flink 2.x recommends Java 17; Java 21 is experimental; Java 23 is not a supported runtime → build/run Flink jobs with a JDK 17 toolchain or inside the Flink image, never with the host JDK.
- `flink-connector-kafka` releases trail Flink core (4.x line targets Flink 2.0) → pin the Flink version to one with a released Kafka connector, not the newest Flink.
- dbt-core 1.12 lists Python 3.14, dbt-postgres 3.14 support unconfirmed → pin the project Python (3.12 or 3.13) in a lockfile; the pack's own floor is 3.11.
- Recent Debezium 3.x dropped PostgreSQL 13 → PostgreSQL ≥ 14 (pin the major tested with the chosen Debezium).
- Full lab (PostgreSQL + Kafka + Connect + Flink JM/TM + MinIO) memory on Docker Desktop must be measured, not assumed.
- Public repo has no LICENSE yet → owner decision before code lands. **Decided 2026-11-20: Apache-2.0 (DEC-0009).**
